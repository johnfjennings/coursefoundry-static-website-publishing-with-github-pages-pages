Step 4: Showcase Your Projects

In this step you write a page for each showcase project, linking to its Git repository, and generate a Projects page that lists them automatically as cards.

Instructions

1. Create a folder for each project

Inside your <username>.github.io repository:

mkdir -p projects/weather-app projects/group-cms

Use short, lowercase, hyphenated names - they become part of the URL (e.g. https://<username>.github.io/projects/weather-app/).

2. Write a project page

Create projects/weather-app/index.qmd and copy in a screenshot as projects/weather-app/screenshot.png:

---
title: "Weather Forecast App"
description: "An Android app that shows 7-day forecasts using the Open-Meteo API."
date: 2024-05-01
image: screenshot.png
categories: [Kotlin, Android, REST API, Solo]
---

[View source on GitHub](https://github.com/<your-username>/weather-app){.btn .btn-primary}
[Live demo](https://<your-username>.github.io/weather-app/){.btn .btn-outline-secondary}

![The forecast screen showing a 7-day outlook](screenshot.png){fig-alt="Phone screen with a list of seven days, each with a weather icon and temperatures"}

## The problem

What need or question did the project address? Who was it for?

## My role

Solo project / team of four - I was responsible for ...

## How I built it

Key technologies, architecture and one or two interesting decisions.
A short code snippet can help:

```kotlin
val forecast = api.getForecast(lat, lon, days = 7)
```

## Outcome

What worked? Grade, users, performance, feedback, awards?

## What I learned

One or two honest reflections - employers value these.
TipWrite for a recruiter, not a marker

Use the Problem - Role - Approach - Outcome - Learning structure. Lead with results, keep paragraphs short, and be specific about your contribution in team projects (“I designed the database schema and wrote the REST API” beats “we built a CMS”).

Repeat for each of the 3-6 projects you chose in Step 1.

3. Turn the Projects page into a listing

Replace the contents of projects.qmd with:

---
title: "Projects"
listing:
  contents: projects
  type: grid
  sort: "date desc"
  categories: true
  fields: [image, title, description, categories]
---

A selection of projects from my studies and spare time.
Each card links to a write-up with source code and demos.

Quarto scans the projects/ folder, reads each page’s front matter and builds a grid of cards with filterable category tags - you never have to edit the list by hand.

4. Link to your other repositories

You don’t need a write-up for every repository. Add a short section to the bottom of projects.qmd for honourable mentions:

## More on GitHub

- [algorithms-practice](https://github.com/<your-username>/algorithms-practice) - solutions to data-structures exercises in Java
- [dotfiles](https://github.com/<your-username>/dotfiles) - my development environment setup
- [All repositories](https://github.com/<your-username>?tab=repositories)

5. Feature projects on the home page (optional)

Add a short “Featured work” listing below your introduction in index.qmd:

## Featured work

::: {#featured}
:::

and add this to the index.qmd front matter:

listing:
  id: featured
  contents: projects
  type: grid
  max-items: 3
  sort: "date desc"

6. Preview and commit

quarto preview

Check every card, link and image, then:

git add .
git commit -m "Add project showcase pages"
git push

Checkpoint

Before moving on, verify that:

Check Your Understanding

You add a new project folder with an index.qmd. What do you need to change in projects.qmd for it to appear as a card?

✗Add a new link to the list in projects.qmd.

✗Add the project to the navbar in _quarto.yml.

✓Nothing - the listing finds pages in the projects/ folder automatically.

What Just Happened?

You connected your portfolio to the evidence behind it. Each write-up gives a recruiter the story, while the repository link lets a technical interviewer inspect the code. Using a listing means adding future projects takes minutes.
